# Threat model

**Assets:** buyers' escrowed ETH, sellers' withdrawable ETH and tips, the
integrity of passes (who holds them, whether they were used).

**Actors:** buyers (Tobi), sellers (Ada), an attacker (Mallory) who can call
anything with any value, deploy contracts, sign anything with her own keys,
and run code when she receives ETH or a token. A malicious seller is in scope
for buyer money: the seller must not be able to take escrow before check-in
or `release_at`, or fake check-ins.

**Trust assumptions:** the EVM and EIP-1153/EIP-6780 semantics on Osaka; Fe
26.6.0 codegen (tested, not audited); block timestamps for `release_at` and
signature deadlines; the holder's key (or ERC-1271 wallet) for check-ins.

**Out of scope:** Sybil resistance of per-wallet caps; a seller who simply
doesn't hold the event after `release_at`; front-ends other than ours; the
faucet's off-chain abuse beyond its rate limits.

## Off-chain

| Risk | Mitigation |
|---|---|
| Burner key theft | keys never leave the device (localStorage, versioned key `till.burner.v1`); "Copy/Download key" for backup; testnet banner on every page |
| Faucet drain | server-side key in env only; address validation (zod); chain check; refuse if balance ≥ 0.01 ETH; per-address cooldown (24 h on Sepolia); per-IP limit; global daily cap; Upstash Redis when configured |
| Wrong network | injected wallets are switched/added to the shop's chain before any send; burner always uses the configured chain |
| Surprise amounts | every write is simulated first; the review sheet decodes line items and the exact total; the contract rejects any other amount |
| Stale prices | prices are read from the chain; a changed price fails simulation and shows "Refresh prices" |
| Forged door codes | the door recovers the EIP-712 signer locally and compares with the current holder before offering Redeem; the contract re-checks on-chain |
| Secrets in git | `.env*` ignored; gitleaks in CI (anvil's public test keys allow-listed) |
